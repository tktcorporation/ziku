`ziku push` が、同じファイルを内容の更新と削除の両方として送らないようにする。

送信内容を 1 パス 1 指示の写像で持つ。内容として載せる操作は、そのパスが削除として載っていれば載せない。テンプレートの README を自動更新する経路も、README を消す push では組み直しを行わない。ローカルで削除した `README.md` を `--include-deletions` で送ると、削除として送りつつ README の自動更新が同じパスを内容としても積み、GitHub が PR の作成を拒んで同期ブランチだけが残っていた。サマリーもそのファイルを `~ modified` として並べ、削除する push だと画面から読み取れなかった。

PR 作成の側でも、内容と削除に同じパスが含まれていれば fork もブランチも作る前に止め、そのファイルを push から外す案内を出す。
