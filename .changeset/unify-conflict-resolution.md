ベースを取得できないコンフリクトで、`ziku pull` が自動マージを行わなくなる。

共通祖先（前回同期時点のテンプレート）を取り直せるのは GitHub ソースかつベースのコミット SHA を記録済みのときだけで、ローカルテンプレートを使う構成では常に取り直せない。この状況で `pull` はベースを空として 3-way マージし、ファイル全文をコンフリクトマーカーで囲んだ内容をローカルへ書き込んでいた。両側を編集するたびに全文がマーカー化されるため、ローカルテンプレート運用では実質的に毎回手作業での復旧が必要だった。

ベースが無い場合は自動マージを試みず、ローカルのファイルには一切書き込まない。対象は「自動マージできなかったファイル」として報告され、ユーザーがローカルとテンプレートを見比べて解決する。`ziku push` は以前からこの扱いだったため、pull と push の判断が一致する。
