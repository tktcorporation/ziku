`ziku init` が lock の同期ベースへ記録するハッシュを、実際にディスクへ載った内容から取る。

上書き戦略が `skip` に解決される実行（`--yes` はプロンプトを省くだけで、既存ファイルを失う承認は含まない）では既存ファイルがそのまま残る。残ったファイルはその内容のハッシュを、`--force` などで書き込んだファイルは書いた内容のハッシュをベースに記録する。`.ziku/ziku.jsonc` も同じ規則で扱い、書き込みが起きたときだけ init が生成した本文（テンプレートの本文ではなく、選択したパターンの部分集合）のハッシュを記録する。

lock のベースは次回の pull / push が差分を測る基準なので、ディスクに存在しない内容を記録すると、誰も編集していないのに次回の比較が差分を報告する。テンプレートを走査したハッシュをそのままベースにしていたときは、保持した既存ファイルが「ローカルがテンプレートの内容を書き換えた」ものに見え、`status` が push を勧め、`push` がユーザーの無関係な既存ファイルでテンプレートを上書きし、`pull` はベースとテンプレートが一致するのでテンプレート版を降ろさなかった。
