GitHub REST API で参照を引けなかったとき、`git ls-remote` で引き直すようにした。

未認証の REST API は IP あたり 60 req/h で、共有 IP から実行する環境ではこの枠が他の利用者と混ざって枯れる。枠が尽きると既定ブランチ名を引けず、テンプレートの取得そのものが始まらない。git のプロトコルはこの枠を消費しないため、参照を引くだけの用途は git 側で足りる。

- 既定ブランチ名（`git ls-remote --symref <url> HEAD`）と、ブランチ / タグが指すコミット SHA（`git ls-remote <url> <ref>`）の 2 か所が対象。テンプレート本体の取得はレート制限の対象外のエンドポイントを使うため変更しない。
- git へ倒すのは、待てば直る失敗（レート制限・接続断・5xx）のときだけ。トークン拒否（401）は人がトークンを直すまで解消しないため倒さず、権限の切れたトークンのまま同期が進むのを防ぐ。git でも引けなかった場合は API 側の失敗理由をそのまま返す。
- 倒したときは切り替えた事実と API 側の理由を stderr へ出す。API が使えない状態は `push` の PR 作成など git で代われない操作で失敗として現れるため、取得だけ通って原因が見えない状態にしない。
- 同名のブランチとタグがある場合はブランチを採り、注釈付きタグはタグオブジェクトではなく指しているコミットの SHA を返す（GitHub の `/repos/{owner}/{repo}/commits/{ref}` と同じ結果になる）。
