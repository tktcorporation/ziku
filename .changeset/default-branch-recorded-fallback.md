GitHub へ一時的に問い合わせられないだけでは、コマンドが止まらないようにする。

`.ziku/lock.json` の `source` に `defaultBranch` を持たせる。`ziku init` はテンプレートリポジトリの既定ブランチを 1 回引いてここへ控える。以降の `pull` / `push` / `diff` / `status` は毎回 GitHub へ既定ブランチを問い合わせ、引けたときはその結果で控えを更新する。`source.ref` は埋めないので、既定ブランチが改名されればそのまま追随する。

既定ブランチを引けなかったときの扱いを、理由で分ける。

- トークンを拒否された（401）: 中断する。トークンを直すまで結果は変わらず、プライベートリポジトリでは見えるはずのものが見えていない。
- レート制限・5xx・ネットワーク断: 控えた既定ブランチからテンプレートを取得して続行し、控えを使ったことを警告として出す。テンプレートの取得（tarball）は GitHub REST のクォータを使わないため、未認証の 60 リクエスト/時を使い切っていても取り込みと差分は成立する。控えが無いときだけ中断する。

控えへ倒しても、取得したツリーと `.ziku/lock.json` に記録する参照は同じブランチを指す。ベースのコミット SHA は取得に使った ref で引き、SHA まで引けなければ `base.ref` を空のまま残す（次回のマージが共通祖先無しへ縮退する）。控えたブランチ名が改名で消えていた場合は、別のブランチのツリーを掴まずに取得の失敗として報告する。

`defaultBranch` を持たない `lock.json` でも読み書きは通るが、控えが無いためレート制限にかかると取得先が決まらない。`ziku init` で作り直すと控えが入る。
