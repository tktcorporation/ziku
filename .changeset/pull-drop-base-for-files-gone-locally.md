`pull` がテンプレート側の削除に対して同期ベースを据え置くのは、ローカルのワークツリーにファイルが実在する場合だけになる。据え置きは、残したファイルが「ローカルにしかないファイル」へ分類されて続く `push` がテンプレートの削除を巻き戻すのを防ぐためのもので、既にローカルから消えているファイルにはその危険が無い。テンプレートにもワークツリーにも無いファイルはベースからエントリが落ち、`ziku pull --yes` を繰り返しても削除候補として報告され続けず、`ziku status` も同期済みへ収束する。

`pull --dryRun` は、コンフリクトの解決待ちで中断するプレビューでは削除に関する予告を出さない。実際の `pull` は中断すると削除の処理へ進まないため、ローカルに編集があるファイルについても削除の見込みは伝えない。
