同期対象のパスを「通常の同期ファイル」と「ziku 自身の設定ファイル（`.ziku/ziku.jsonc`）」の判別 union で表現し、種別ごとの扱いを 1 箇所へ集約する。

`ziku.jsonc` は「常に追跡する / 内容は加法 union でマージする / 削除は伝播しない」という他の追跡ファイルと違う規則で扱われるが、型の上では区別が無く、規則の実行がパターン解決・ハッシュ計算・diff 検出・pull / push / status の分類消費へ分散していた。分類結果は設定ファイルを含まない `files` と、設定ファイルの位置づけを表す `config` に分けて返す。pull / push / status は分類から設定ファイルを自分で抜き出さず、種別ごとの判断関数（`match().exhaustive()`）が返した扱いを実行する。

外部から見た挙動は変わらない。特別扱いのファイルが増えたときは、種別の追加が仕分けと各コマンドの扱いをコンパイルエラーとして知らせる。
