フラグの意味をコマンド間で統一する。`--force` は破壊的な操作（既存の内容を失う操作）の承認、`--yes` / `-y` は対話プロンプトの省略を表し、`--yes` は破壊的操作を承認しない。

- `ziku pull` の `--force` は「テンプレートで削除されたファイルをローカルからも削除する」承認になる。プロンプトの省略は `--yes` が担い、`--yes` だけで実行した場合これらのファイルは削除されずに残る（残した件数と `--force` の案内をログに出す）。ローカルに編集があるファイルは、どちらのフラグでも削除せず対話で選んだものだけを削除する。
- `ziku push` の `-f` は使えなくなる。確認の省略は `-y` / `--yes` を使う。`-f` / `--force` を渡した実行は、代わりに使うフラグを案内して中断する。
- `ziku push --yes` は未追跡ファイルの追跡選択も省くため、push から外れた件数と理由を通知する。
- `ziku init --yes` は上書き戦略に `skip` を選ぶ。既存ファイルを上書きするには `--force` か `--overwrite-strategy overwrite` を明示する。

引数なしで実行したときの対話メニューに `setup` と `track` を追加する。

サブコマンド名に近い第 1 引数（`ziku pul` など）は init として実行せず、候補を提示して中断する。`ziku .` や `ziku ./my-project` のようなパス表記はこれまでどおり init として動く。
