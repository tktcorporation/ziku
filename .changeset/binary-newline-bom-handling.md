改行コード・BOM・バイナリファイルを壊さずに同期する。

ファイルのハッシュをバイト列から計算する。テキストのハッシュ値は utf-8 のバイト列と同じなので、既存の `.ziku/lock.json` はそのまま使える。バイナリを utf-8 としてデコードしてから計算していたときは、テキストとして解釈できないバイトが同じ置換文字へ潰れ、内容の違う画像やフォントが同じハッシュになって「変更なし」と判定されていた。

バイナリを行単位のマージ対象から外す。先頭 8000 バイトに NUL があるかで判定する（git と同じ基準）。ローカルとテンプレートの両方が変更されたバイナリは、マーカーで囲んだ結果を書き戻さず「自動マージできない」として未解決にし、どちらの版を採るかをユーザーへ渡す。

バイナリをテンプレートへ送るとき、元のバイト列のまま PR に載せる。差分表示では内容を並べず `Binary files ... differ` の 1 行にする。

マージの内部で改行コードと BOM を揃え、結果はローカル側の形へ戻す。片側が LF・片側が CRLF というだけで全行が衝突していたのが、内容の変更だけを差分として扱うようになる。生成するコンフリクトマーカーもそのファイルの改行コードに従う。改行コードが混在するファイルは多数派へ揃える。ハッシュ比較では正規化しない（改行コードや BOM が違うファイルは実際に違うため、差分として検出する）。
