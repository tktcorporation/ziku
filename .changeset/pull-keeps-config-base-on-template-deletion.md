テンプレートが `.ziku/ziku.jsonc` を削除しても、`pull` が同期ベースのエントリを落とさない。

ベースが落ちると、次の分類は「ベース無・ローカル有・テンプレート無」＝ `localOnly` になる。`localOnly` は `push` の既定送信集合で、テンプレートの削除を取り消す操作だという印も付かないため、続く `ziku push --yes` が確認なしに設定ファイルを復活させる PR を立てていた。その内容はそのプロジェクトの include パターンそのもので、マージされると加法 union で全プロジェクトへ配られる。

pull における設定ファイルの扱い（`ZikuConfigPullAction` / `ZikuConfigMergeResult`）が、ローカルの内容とベースの行き先を必ず値として表明する形になった。設定ファイルは仕分けの時点で通常の同期フローから外れ、削除候補としてベースを据え置く経路を通らないので、ベースの扱いを表明しない値を置くと「テンプレートの走査結果に従う」という既定へ黙って落ちる。テンプレートが削除しローカルに残るならベースを据え置き、両側から消えていればベースからも落とす。
