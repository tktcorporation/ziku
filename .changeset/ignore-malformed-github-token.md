`GITHUB_TOKEN` / `GH_TOKEN` に GitHub トークンの形をしていない値が入っている場合、その値を無視して未認証で続行するようにした。

トークン以外の定型値（サンドボックス実行環境が `GITHUB_TOKEN` に置くプレースホルダ等）をそのまま Authorization ヘッダに載せると GitHub は 401 を返し、ziku は 401 を「人がトークンを直すまで解消しない失敗」として扱うため、未認証なら取得できる public テンプレートの取得まで中断していた。

- 判定は接頭辞（`ghp_` / `gho_` / `ghu_` / `ghs_` / `ghr_` / `github_pat_`）と接頭辞導入前の 40 桁 16 進数で行う。使えるトークンかどうかは GitHub の 401 に委ね、ここでは「トークンかどうか」だけを見る。
- 無視した場合は変数名を添えた警告を出す（1 コマンドの実行につき変数ごとに 1 回）。黙って未認証へ倒すと、private リポジトリでは 404 という無関係な症状に化けるため。
- 同じ判定を `gh auth token` の出力にも適用する。GitHub Actions が `GITHUB_TOKEN` に入れる `ghs_` から始まる installation token も受け付ける。
