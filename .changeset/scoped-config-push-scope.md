`ziku push` が、今回の push に関係するローカル限定パターンだけをテンプレートの `ziku.jsonc` へ届けた状態を、次の push まで保つ。スコープを絞って送った `ziku.jsonc` はローカルへ書き戻さないので、その同期ベースも前進させない。ベースを据え置くことで、テンプレート側の追加は次の分類でも「テンプレートだけが変えた」ままになり、続けて `ziku push --yes` を実行しても無関係なローカル限定パターンがテンプレートへ渡らない。テンプレート側の追加を取り込むのは `ziku pull` の役目になる。

ローカルにしか無いパターンが 1 つも無いときは、`ziku.jsonc` をテンプレートへ送らない。加法 union はテンプレートの内容と一致するため、送るとパターンが 1 つも増えない `ziku.jsonc` だけの PR が立つ。この判断は `ziku status` の表示カテゴリと同じ経路から導くので、status が pull だけを勧めた状態で push が PR を作ることはない。

`ziku push --dry-run` が予告するテンプレート README の更新を、GitHub への push のときだけに限る。README の自動更新は PR を作る経路でしか走らないため、ローカルテンプレートへの push では起きない更新を予告していた。
