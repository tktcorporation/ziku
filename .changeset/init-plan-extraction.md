`ziku init` の「何を配置し、どんな lock を書くか決める計算」を I/O とプロンプトから切り離す。

引数とテンプレートのパターンから配置対象を決める判断、`--force` / `--overwrite-strategy` / `--yes` / 対話の優先順、テンプレートソースの解決結果（見つかった / 見つからない / 曖昧 / 検出不能 / 確認不能）に対する次の行動、lock の同期ベースと初期状態の組み立てを `src/commands/init-plan.ts` へ移し、`init.ts` はファイルシステム・GitHub API・プロンプトと、決まった計画の実行だけを担う。

`.ziku/ziku.jsonc` の base をローカル側（部分集合）に置いてテンプレートのパターンを削らせない安全装置、テンプレートに `ziku.jsonc` が無いときに base を記録しない誤削除防止、ハッシュが取れないときにベース未確定（`pending`）のまま残す扱いはそのまま保つ。CLI の挙動・出力は変わらない。
