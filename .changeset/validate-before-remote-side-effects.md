`ziku setup --remote` が、既に設定済みのテンプレートへ PR を作らないようにする。

`--yes` を付けた実行でも、対象リポジトリに `.ziku/ziku.jsonc` があれば「設定済み」と伝えて終わる。これまではリポジトリの存在だけを確かめていたため、既存の `ziku.jsonc` を規定パターンで置き換える PR ができ、タイトルも本文も「追加」としか書かれていないままマージされると、そのテンプレートを使う全プロジェクトの同期対象が規定値へ戻っていた。作るか何もしないかの判断は、ローカル実行とリモート実行で同じ 1 本を通る。

設定済みかを確かめられなかった場合（GitHub へ届かない等）は警告して進むが、PR に載せるファイルが宛先に既にあれば、ブランチもコミットも作る前に止まる。

あわせて、PR 作成の検証をすべて副作用より前へ移した。ツリーを取り切れない場合と削除対象が宛先に無い場合は、これまで fork に同期ブランチを作った後で失敗しており、案内どおり `ziku pull` を挟んで再実行するたびに使われないブランチが増えていた。今は fork の作成もブランチの作成も、確認がすべて終わってから行う。
