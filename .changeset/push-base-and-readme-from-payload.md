push が送った内容とローカルの状態が食い違ったまま同期ベースを進めないようにする。

自動マージした衝突を送った後の同期ベースは、送る前の値に据え置く。マージ結果はテンプレートへ届くだけでローカルのファイルには残らないため、ベースをテンプレート側へ進めると次の分類がそのファイルを「ローカルだけが変えた」と読み、続く `ziku push --yes` が古いローカル内容を送ってテンプレート側の変更を巻き戻していた。ベースを進めるのは、送った内容がローカルにも残るパスと、push 前からローカルとテンプレートが一致していたパスだけになる。テンプレート側の変更を取り込むのは `ziku pull` の役目のままで、push はローカルのファイルを書き換えない。

テンプレートの README を PR に載せるとき、同じ PR に載る内容から組み直す。README が同期対象として追跡されていても、同じパスを 2 度送らない（2 度送ると 2 回目の書き込みが弾かれ、ziku の不具合として報告されていた）。組み直しの土台には追跡ファイルとして送るローカルの内容を使い、その中のマーカー間だけを `ziku.jsonc` から組み直す。生成元の `ziku.jsonc` も同じ PR に載る内容を使うので、`ziku track` で足したばかりのパターンが README に反映される。

GitHub が宛先を見つけられなかった場合 (404) を、対処できる失敗として案内する。`.ziku/lock.json` に控えた既定ブランチが上流で改名・削除されると PR の作成先が存在しなくなる。`source.ref` でブランチを明示する・`ziku init` で lock を作り直す、といった直し方を示す。
