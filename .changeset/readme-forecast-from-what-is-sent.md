`ziku push --dry-run` のテンプレート README の予告を、実 push が送る内容そのものから出す。同じ push が `ziku.jsonc` の変更を運ぶとき（`ziku track` で足したパターンをテンプレートへ届ける場合など）に、予告が「何も起きない」と言いながら実 push が `README.md` を PR へ載せることがなくなる。追跡ファイルとして選ばれた README を土台に組み直す点も予告と実 push で一致する。

あわせて到達しないコードを整理した。GitHub API の失敗の分類は API を呼ぶ側だけが持ち、push コマンドは分類済みの失敗をそのまま運ぶ。`--from` の解決は存在確認を伴う経路だけに絞る。失敗文言が英語で書かれているかの検査は、ソースの行ではなく `describeFailure` の戻り値を見るので、複数行に分かれた hint も検査に入る。
